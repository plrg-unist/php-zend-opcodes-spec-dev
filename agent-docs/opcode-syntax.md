# Concrete syntax for opcode fixtures

The native extension and Rust library read and write one compilation unit as line-oriented text. Numeric flags and cache layout follow the pinned Zend build. Use it for trusted test programs. [Complete hand-written unit](../tests/project/handwritten.zop) · [Native unit reader and writer](../ext/unit.c) · [Rust library](opcode-ast.md)

## Unit and body layout

The first line is `zend-opcodes`. The next line gives the logical `file` name, followed by an optional compiler halt offset and ordered `autoglobal "NAME"` rows when compilation activated a lazy superglobal. The `main` body comes first, followed by named functions and classes and a final `end`. A body gives its name (`-` for main), source lines, frame and cache sizes, declarations and ordered literals. Nested bodies precede the `code` rows. Class entries describe methods, properties, constants and linkage. [Body grammar](../ext/body.c) · [Enum cases](../ext/enums.c)

## Printing and parsing conventions

- Use one instruction per line. Read its body-local index, optional `result =`, mnemonic, then `op1` and `op2` in that order, separated by a comma. A trailing empty operand can be omitted. Use `_` if an empty first operand precedes a meaningful second operand. Keep `OP_DATA` at its own index.
- Use the engine’s `CV`, `T` and `V` slot notation. `@4` denotes instruction 4 in this body. A bare integer, such as the argument position in `RECV 1`, is an immediate. `lit[n]` references entry `n` in the ordered literal pool. Pool order matters because some handlers also read the entry following an operand’s literal. [Paired name literals](../../php-src/Zend/zend_compile.c#L633) · [VM lookup](../../php-src/Zend/zend_vm_def.h#L3704)
- Each CV in a body has a unique byte-string name. The cache offsets used by `FETCH_CONSTANT`, `DEFINED` and `BIND_GLOBAL` are aligned, body-local byte offsets. Constant lookups can share a slot and observe the cached binding. `BIND_GLOBAL` uses a different slot representation. Give it a separate offset in the same body. [Shared constant slot](../tests/project/constant_cache_slots.zop) · [Incompatible slot](../tests/project/invalid/constant_global_cache.zop)
- `numeric-string-key` marks an integer literal whose next pool entry holds the original string. One annotated dimension instruction sets the flag for every use of that literal in the body. The native printer repeats it on qualifying uses. A string-offset handler may read either the integer or its companion, depending on the opcode and container operand. [Hand-written regression](../tests/project/string_offset_literal_companion.zop)
- `array("answer" => int(42))` creates a fresh ordered array with a byte-string key. Quote byte strings, escape quotes and backslashes, and use `\xHH` for non-printable bytes. Give floating-point values a spelling that round-trips exactly.
- `array(packed=16; 0 => int(7))` specifies packed storage with room for 16 slots. Use a power-of-two capacity from 8 through `2^30` on the pinned 64-bit build. Packed keys are strictly increasing nonnegative integers below that capacity. `array(mixed; 0 => int(7))` specifies mixed storage. Omitting the marker retains the layout produced by inserting the listed keys in order. This distinction can change the next `[]` key after a sparse insertion and deletion. [Packed capacity](../tests/project/array_literal_packed_capacity.phpt) · [Folded mixed table](../tests/project/array_literal_folded_mixed.phpt)
- The marker also works inside `array#7(...)` and on empty arrays. For example, `array(packed=8; next=1)` has no entries. Even an empty packed source can affect a later `[]` when unpacked into another array. [Shared literal](../tests/project/array_literal_shared_layout.zop) · [Empty unpack source](../tests/project/array_literal_empty_unpack.zop)
- `mixed=8; holes=[1, 3];` gives the mixed table’s capacity and deleted bucket positions. Write the live entries in iteration order. Use `cursor=N` for an ordinal among live entries or `position=N` for a physical bucket position with an explicit capacity. A physical position can survive beyond the last used bucket after compaction. Packed holes follow their integer keys. A single `array#N` binding can preserve immutable copy behavior when mutable duplication would compact holes. A binding containing a deferred expression, even in a nested array, stays mutable. [Folded mixed literal](../tests/project/cursor_layout_folded_holes.phpt) · [Three cursor positions](../tests/project/cursor_layout_rebind.zop) · [Deferred array](../tests/project/foreach_cursor_deferred.zop)
- Write a shared literal array as `array#7(0 => int(42))` at its first occurrence and `array-ref(7)` on reuse. A label is a unique unsigned 32-bit integer in the compilation unit. A reference requires an earlier completed binding. Keep the outer `statics` table and switch/match jump-table literals plain. Arrays stored in static variables, declaration metadata and ordinary literals can share bindings. [Native literal codec](../ext/text.c) · [Rust literal codec](../src/values.rs)
- Loading a partial callable freezes its masked constant arguments. If another instruction uses the same literal slot, array copying can observe this even when the partial call is unreachable. Identify the owning call site and mask during preparation. In an executable unit, check each body before entering main. A selected array containing a deferred expression is malformed. Extend call-target resolution when class methods enter scope. [P4 preparation](../spec/02-vm/17-literal-preparation.watsup) · [Dormant partial](../tests/project/foreach_cursor_dormant_partial.zop) · [Malformed nested body](../tests/project/invalid/partial_deferred_nested_body.zop)
- Canonical rows include their source line, e.g. `1: JMPZ CV0, @4 | line=7`. Fields after `|` also describe extended operands, cache slots, smart branches and special literal metadata. For optimized partial application, `bound-mask=N` preserves which prefix arguments Zend binds as constants. The printer clears OPcache's shared-memory eligibility bit because loaded closures live in request memory. Switch/match table values are body-local instruction indices. [Instruction codec](../ext/instructions.c)
- Attribute records and deferred constant expressions include their arguments or expression nodes. A deferred closure contains a nested executable body. [Attributes](../ext/attributes.c) · [Deferred expressions](../ext/constant_ast.c)
- `CONCAT`, `FAST_CONCAT` and rope instructions require byte strings in literal operand positions. Use a slot for a value that needs conversion. `CONCAT` requires at least one slot operand. Keep the result of `ROPE_END` outside its rope's temporary storage. [Valid ropes](../tests/project/rope_indices.zop) · [Rejected forms](../tests/project/invalid)
- For a hand-written numeric instruction, use an operand kind accepted by its pinned handler. A `V` slot is valid for `ADD` but is rejected for `DIV`. Installing a handler can also exchange the two operands of operations such as `MUL`, which can affect diagnostic order. [Instruction validation](../ext/validate.c) · [Rejected numeric operand](../tests/project/invalid/numeric_operand.zop)
- Parsing checks operand shapes, references, jump tables, companions and call-frame metadata before execution. Treat hand-written programs as trusted code. An already-linked class containing composed traits can lack the information needed to recover its original declarations and is rejected explicitly. [Validation](../ext/validate.c)
