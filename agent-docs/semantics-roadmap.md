# Execution semantics milestones

Implement a single P4-SpecTec execution semantics over the existing `unit`. Extend each operation as new operands, callbacks, failures and cleanup become observable. Builtins can first appear through specialized oplines and gain their other call forms in milestone 4. The [opcode assignments](semantics-opcodes.md) identify where each mnemonic enters. The [agreed scope](semantics-scope.md) defines the runtime and outcomes.

## Targets and acceptance

1. **Run main.** The [execution rules](../spec/02-vm/00-core.watsup) implement the first nine opcodes. The main frame tracks its instruction index, literal pool, slots and emitted stdout. Scalar assignment and return support integers, byte strings, booleans and null. Increment and comparison support integers with in-range results, conditional jumps consume booleans, and `ECHO` writes integers and byte strings. M1 has no builtin, stdin read or stderr write. Main return ends execution with PHP status zero.

   The [branch](../tests/php-src/tests/lang/001.phpt) and [loop](../tests/php-src/tests/lang/002.phpt) use smart comparisons. The [standalone branches](../tests/project/standalone_branches.zop) and [assignment results](../tests/project/variable_results.zop) expose direct jumps, binary output, early return and used result slots. A reached future operation preserves prior output. Class installation can require unsupported work before main. Uncalled ordinary functions and empty hidden class declarations can stay dormant. Hidden classes with method metadata can emit diagnostics during registration. [Dormant declarations](../tests/project/dormant_class.php) · [Method registration fixture](../tests/project/hidden_magic_method.zop)

2. **Scalars and control flow.** Apply the milestone completion checks to each part.

   - **2A. Scalar values and strings.** Main handles undefined reads and their default diagnostics, scalar truth and type tests, concatenation and interpolation, and the opcode forms of `strlen` and `gettype`. `TYPE_CHECK` covers `is_null`, `is_bool`, `is_int`, `is_float`, and `is_string`. Tests expose the false string `"0"`, signed zero, NaN warnings, embedded NUL bytes, and both weak and strict `strlen`. Scalar conversions that need decimal float formatting enter in 2B. A strict type error that needs a catch or finally stops at the milestone 6 boundary. [Scalar rules](../spec/01-values/01-core.watsup) · [String rules](../spec/02-vm/03-strings.watsup) · [Cases](../tests/semantics.json)
   - **2B. Numeric behavior.** Scalar main evaluates numeric strings and casts, signed 64-bit and binary64 arithmetic, overflow, division, shifts, byte-string and integer bitwise operations, pre/post increment and decrement, and loose, strict and three-way comparisons. The spec controls coercion, precision, diagnostic order, compound writes and smart branches. Five pure Rust primitives handle binary64 conversion, arithmetic, truncation, decimal parsing and formatting. Check multiple rounding boundaries, signed zero, NaNs, and malformed exponent suffixes against the pinned CLI. [Coercions](../spec/01-values/02-numeric-conversions.watsup) · [Arithmetic](../spec/01-values/03-arithmetic.watsup) · [Bitwise operations](../spec/01-values/04-bitwise.watsup) · [Comparisons](../spec/01-values/05-comparison.watsup) · [Increments and decrements](../spec/01-values/06-incdec.watsup) · [Binary64 interface](../spec/01-values/00-binary64.watsup)
   - **2C. Control flow.** Short-circuit jumps preserve the selected value or write a boolean according to the opcode. Null coalescing silently reads an undefined variable. Nullsafe chains distinguish ordinary, `isset`, and `empty` reads. A switch table with the wrong selector type falls through to the loose case comparisons. A match table uses exact integer or byte-string keys and takes its default on a miss. An unhandled `MATCH_ERROR` enters in milestone 6. [Branch rules](../spec/02-vm/01-branches.watsup) · [Switch and match rules](../spec/02-vm/02-cases.watsup) · [Observable branch results](../tests/project/branch_result_slots.zop) · [Dispatch cases](../tests/project/dispatch_match.php)

3. **Arrays, variables and references.** Apply the completion checks to each part.

   - **3A. Array values and reads.** Construct and unpack ordered arrays, convert keys, read elements, and distinguish missing keys from null values. Cover array truth, comparisons, and the specialized forms of `count`/`sizeof`, `is_array`, `array_key_exists` and `in_array`. Preserve entry order, append index, cursor and sharing. With `NAN` as an element, a copied array compares identical to the original, while a separately constructed array can compare unequal. [Array values](../spec/01-values/07-arrays.watsup) · [Comparison](../spec/01-values/08-array-comparison.watsup) · [Element and builtin reads](../spec/02-vm/05-array-reads.watsup)
   - **3B. Writes and ordinary copies.** Cover nested writes, appends, unset, compound assignment, byte-string offsets, by-value destructuring, array casts and union. A writable fetch retains the selected bucket across subsequent instructions. Separate a shared array on mutation, including a missing-key unset when separation changes a later observation. The next append can depend on packed capacity, the history of deleted keys, or whether an empty array still has another owner. String-offset instructions differ in their use of a numeric key’s original spelling. [Locations and copies](../spec/02-vm/06-locations.watsup) · [Array updates](../spec/01-values/10-array-updates.watsup) · [String offsets](../spec/02-vm/08-string-offsets.watsup) · [Destructuring](../spec/02-vm/09-destructuring.watsup)
   - **3C. References and iteration.** Reference assignment, array construction and destructuring can bind variables and elements to one cell. On array duplication, whether another owner still shares a cell can determine which array a later write changes. By-value `foreach` retains its source. By-reference iteration follows changes to the source, including rebinding to an array with an existing cursor. The `.zop` codec retains mixed-table holes and physical positions for that case. [Reference cells](../spec/02-vm/12-reference-cells.watsup) · [Iteration](../spec/02-vm/15-foreach.watsup) · [Physical array positions](../spec/01-values/15-table-positions.watsup) · [Rebinding regression](../tests/project/cursor_layout_rebind.zop)
   - **3D. Variable names, globals and constants.** Main binds named fetches and compiled locals to the same symbol table. A `$GLOBALS` snapshot preserves visible order and reference ownership. Even an undefined CV can affect the resulting array layout after a numeric key is inserted. [Symbol table](../spec/02-vm/17-symbol-table.watsup) · [Named variable operations](../spec/02-vm/18-named-variables.watsup) · [Hidden numeric CV](../tests/project/global_hidden_numeric_cv.php)

     Named constants use the unit’s halt offset, a request-local declaration table and the supplied runtime constants. Preserve each instruction’s name-literal group and cache offset. An earlier namespace fallback can stay cached after a namespaced declaration. The two compiler profiles can legitimately observe different bindings. [Constant lookup](../spec/02-vm/20-constants.watsup) · [Deferred expressions](../spec/02-vm/21-constant-expressions.watsup) · [Cache regression](../tests/project/review_constant_namespace_cache.php)

     Check the reference catalog and custom runtime constant inputs on the same finalized listing, including name availability, typed values and deprecation diagnostics. The reference `STDIN`, `STDOUT` and `STDERR` are distinct resource values with observable casts, comparisons and array-key diagnostics. Milestone 4 models I/O on these three streams. Other positive handles remain valid as resource values. [Runtime constant inputs](../design-docs/execution-io.md#runtime-constants) · [Catalog fixture](../tests/project/builtin_constants_catalog.phpt) · [Installation inputs](../tests/project/installation_inputs.php) · [Stream resource fixture](../tests/project/standard_stream_values.phpt)

4. **Calls, closures and standard streams.** Add user and internal frames, conditional declarations, name resolution, recursion, statics, captures, defaults, named/variadic/by-reference arguments and returns. Include direct, dynamic, namespaced, specialized and frameless calls, retaining differences Zend exposes. Target `func_num_args`, `func_get_arg`, `func_get_args`, `call_user_func`, `call_user_func_array`, `function_exists`, `define`, `defined`, `constant`, `assert`, `abs`, `substr`, `array_keys`, `array_values`, `array_slice`, `array_map`, `implode`, and scalar/array `var_dump` and `print_r`. Add `fread`, `fgets`, `feof`, `fwrite` on the standard handles and `exit`/`die`. Test a named by-reference argument, namespace fallback after a conditional declaration, and binary stdin copied to stderr with exit status 7. Test reads at EOF. [Frameless lookup](../../php-src/Zend/zend_vm_def.h#L9950)

   Apply the cumulative completion checks to each part, as for milestones 2 and 3.

   - **4A. Direct calls and frames (complete).** Direct calls enter an unconditional unit-defined function with untyped positional value parameters or invoke the ordinary `strlen` builtin. A return restores the caller's locals, pending calls and iterators. Calls to the same body share its literal identities and cache. The fixtures exercise nesting, recursion, argument side effects, discarded returns and exact uncaught traces. The cumulative suite passed 1,032 cases and exercised all 4,744 spec instructions. [Call frames](../spec/02-vm/23-call-frames.watsup) · [Nested recursion](../tests/project/call_nested_recursion.php) · [Body-local literals and caches](../tests/project/call_body_literals_and_constants.php) · [Trace arguments](../tests/project/call_trace_arguments.php)
   - **4B. Argument binding and function state.** Add defaults, named and variadic arguments, unpacking, reference parameters and returns, return checks, argument inspection and static locals. Check that a named reference updates the caller and that a static local survives a second call.
   - **4C. Function lookup, closures and callbacks.** Add the build's builtin-function inventory, conditional declarations, namespace fallback, dynamic calls, first-class function callables, captures, `function_exists`, `call_user_func` and `call_user_func_array`. Use the inventory to reject two hand-written cases accepted by the 4A validator. Zend rejects an `INIT_FCALL` to a nonexistent function even in dead code. It also rejects a user declaration that collides with an installed builtin such as `getenv`. Check lookup before and after a conditional declaration and a callback that changes a captured variable.
   - **4D. Builtins and optimized call forms.** Cover the planned scalar, array, constant, assertion and output builtins across their ordinary, specialized and frameless forms where Zend emits them. Exercise a builtin such as `array_map` invoking a user callback and compare the observable effects of ordinary and optimized calls.
   - **4E. Standard streams and exit.** Model reads, writes and EOF on the three standard handles, plus `exit` and `die`. Copy binary stdin to stderr, read again at EOF, and exit with status 7.

5. **Objects and class binding.** Add object identity, class and interface lookup, inheritance, construction, cloning, instance/static methods and properties, visibility, late static binding and class constants. Enforce parameter, property and return types for the supported cases. Cover `stdClass`, the core throwable hierarchy, `is_object`, `get_class`, `get_called_class`, `class_exists` and `Countable`. Test `count($object)` calling a unit-defined method that mutates a property. Counting an ordinary `stdClass` raises `TypeError`. [Zend count dispatch](../../php-src/Zend/zend_vm_def.h#L9619)

6. **Exceptions and runtime diagnostics.** Implement cross-frame throw/catch, finally, exception chaining, unfinished calls and cleanup through exception regions and live ranges. Cover implicit errors, unmatched `match`, assertion failures, warnings and deprecations. Add handler masks, suppression, fallback and last-error state for `set_error_handler`, `restore_error_handler`, `error_reporting`, `trigger_error`, `error_get_last`, `error_clear_last`, `set_exception_handler` and `restore_exception_handler`. Check [a throw inside finally](../tests/php-src/Zend/tests/try/try_finally_002.phpt) and the same missing array key with default handling, a handler returning false and a handler throwing. The handler sees PHP severity, message, filename and line.

7. **Advanced declarations and implicit calls.** Cover traits and adaptations, enums and their lookup methods, typed/readonly properties and asymmetric visibility, property hooks, magic methods, union/intersection types, attributes, and deferred defaults that can construct objects or closures. Extend callables to invokable objects, method closures and partial application. Exercise `Stringable`, `ArrayAccess`, `Iterator`/`IteratorAggregate`, local autoload callbacks and object inspection. Limit Reflection initially to unit-declaration reads used by fixtures, such as attributes and arguments, parameter types, doc comments, setter visibility and closure captures. Test the [trait and hook](../tests/project/trait_methods.php), [deferred expressions](../tests/project/constant_expressions.php) and [partial callables](../tests/project/partial_application.php). The exporter currently rejects already-linked trait compositions. Resolve the representation gap for affected in-scope inputs or report it as outstanding. [Exporter check](../ext/unit.c#L121)

8. **Lifetime and request shutdown.** Account for observable destruction on overwrite, unset, temporary release and unwinding. Run explicit `gc_collect_cycles` on the spec’s current heap. Cover `WeakReference`, `WeakMap`, `register_tick_function`, `unregister_tick_function`, `register_shutdown_function` and the ordinary `ob_start`/`ob_get_clean`/`ob_end_flush` output-buffer operations. Check immediate destructor output when the last reference disappears. With a pending finally, a shutdown callback and exit status 7, check that `exit` skips the finally and still runs shutdown processing. [Automatic collection decision](../design-docs/automatic-cycle-collection.md) · [Shutdown order](../../php-src/main/main.c#L1954)

9. **Generators, fibers and final coverage.** Implement generator frames, keys/values, `yield from`, send, throw, return and close. Include the core `Fiber` API for cooperative suspension and resumption of a call stack within the request. Test [nested generator delegation](../tests/php-src/Zend/tests/generators/yield_from_array.phpt), finally on disposal of a suspended generator, and fiber suspend/resume/throw across a nested call. Recheck interactions with callbacks, unwinding and shutdown. [Generator API](../../php-src/Zend/zend_generators.stub.php) · [Fiber API](../../php-src/Zend/zend_fibers.stub.php)

## Completion checks

- Expand the corpus at every milestone. Keep existing fixtures and add focused programs or stdin cases for newly supported behavior, edge cases and regressions. Compare the same listing and stdin against Zend in both profiles. Before reporting completion, run `./scripts/test_semantics.py` without fixture paths, require 100% cumulative spec instruction coverage, and independently review whether the tests expose wrong results and exercise the relevant combinations. [Standalone Python test and coverage gate](differential-testing.md#spec-coverage)
- A required supported case must execute. Unexpected `UNSUPPORTED`, a stuck rule, or any mismatch against the expected stdout, stderr or exit status fails the test. Report a proposed observable departure from Zend as soon as it arises. [Choosing what to model](semantics-scope.md#choosing-what-to-model) · [Test expectations](differential-testing.md#spec-executable-and-differential-suite)
- Test malformed input and deliberately excluded paths with their own expectations. Include an untaken excluded instruction. Check actual instructions and executed effects when the optimizer can fold away the case under test.
- Finish with a disposition for all pinned mnemonics, their in-scope operand and metadata variants, and behavior triggered outside instruction dispatch. Revisit earlier operations as types and callbacks enter. The proposed library covers the named operations and protocols. Availability queries such as `function_exists('getenv')` must reflect the pinned build even when invoking that function yields `UNSUPPORTED`. A genuinely missing function follows PHP's error path.
