# Compiling PHP fixtures to an opcode AST

Use a regular shared PHP extension to capture one compilation unit at a time. The extension prints the same concrete opcode syntax used for hand-written examples. The Rust importer parses it into the program value declared by the `.watsup` syntax. [Fixture syntax proposal](opcode-syntax.md) · [Pinned engine, module build and optimizer profiles](fixture-compilation.md) · [While runner example](../../while-example/src/main.rs#L60)

## Where to capture

At request startup, save the installed `zend_compile_file` pointer and wrap it. Record the starting positions of the function and class tables, call the previous compiler, then inspect the successful return and the new declarations while they are live. The returned `zend_op_array` is the finalized main body for the selected profile. At this point jumps are fixed and live ranges are available. The lint path then destroys the main body without executing it. Write the export to its own output so the CLI lint message stays separate. [Compiler hook](../../php-src/Zend/zend_compile.h#L895) · [Lint entry point](../../php-src/main/main.c#L2766) · [Pass two](../../php-src/Zend/zend_opcode.c#L1102) · [How OPcache identifies a file’s declarations](../../php-src/ext/opcache/ZendAccelerator.c#L1848)

## What the importer needs

- **Bodies and declarations.** Capture main, named functions, classes, their own concrete methods and property hooks. Follow `dynamic_func_defs` recursively from every body and retain each parent’s index-to-body mapping for declaration opcodes. Preserve declaration keys, scopes and binding relationships. Defaults and other deferred constant expressions can themselves contain a `ZEND_AST_OP_ARRAY` with a closure body. [Ordinary body traversal](../../php-src/Zend/Optimizer/zend_optimizer.c#L1535) · [Closure in a constant expression](../../php-src/Zend/zend_compile.c#L12257)
- **Instructions.** Preserve opline order, opcode, operand and result tags and payloads, `extended_value` and source line. Keep companion rows such as `OP_DATA`. Interpret fields per opcode. An `IS_UNUSED` operand can hold a target or a declaration index. Use `RT_CONSTANT` for literal references, `EX_VAR_TO_NUM` for frame slots and `OP_JMP_ADDR` for ordinary jumps. Switch and match tables and their default targets need separate decoding. Export body-local instruction indices and symbolic references in place of addresses. [Instruction layout](../../php-src/Zend/zend_compile.h#L137) · [Addressing macros](../../php-src/Zend/zend_compile.h#L759) · [Opcode-specific fixups](../../php-src/Zend/zend_opcode.c#L1157)
- **Values and metadata.** Preserve the ordered literal pool, including deferred expressions, binary strings, exact numeric values and arrays with their key types and insertion order. Include local names, temporary counts, argument and return information, relevant flags, static initializers, exception regions and live ranges. Class features additionally need class metadata such as parents, properties, defaults and constants. [Body fields](../../php-src/Zend/zend_compile.h#L533) · [Class fields](../../php-src/Zend/zend.h#L147)
- **Other engine tables.** Resolve a frameless internal call’s index through `zend_flf_functions` to identify the builtin. `__halt_compiler()` registers a file-specific offset in `EG(zend_constants)`. Capture such dependencies as their features enter the spec and report unsupported forms explicitly. [Frameless call lookup](../../php-src/Zend/zend_frameless_function.h#L38) · [Halt offset registration](../../php-src/Zend/zend_compile.c#L10563)

## Evidence and scope

At the same path, `<?php return ['answer' => 41];` and its `42` variant produced byte-identical phpdbg listings (`-p`) and byte-identical OPcache listings before optimization (`0x10000`). Both showed `RETURN array(...)`. A temporary compile-hook extension read the string key and the distinct integers through the return operand. The same printer also formats doubles with `%g` and summarizes deferred expressions by type. [Literal printer](../../php-src/Zend/Optimizer/zend_dump.c#L49) · [OPcache dump stages](https://www.php.net/manual/en/opcache.configuration.php#ini.opcache.opt-debug-level)

A second fixture began with an unconditional throw. Lint succeeded and the probe found a `MATCH` table with shared and default destinations, a string containing a NUL byte, a conditional function with nested closures, a closure in a parameter default, a property getter, and a method’s exception-table entry. Two fresh processes produced identical probe output. This exercised representative forms. Each additional opcode or metadata form still needs an explicit mapping.

A file compilation unit contains the file’s main body and the declarations compiled from that file. `include` and `require` emit an instruction in the caller. Their target files are separate units and can be compiled individually. `eval` compiles a string as its own unit when reached. Dynamically chosen inputs and builtin behavior come from the execution environment. [Runtime compilation](../../php-src/Zend/zend_execute.c#L5354)

Hand-written terms can cover VM-created instructions such as `ZEND_HANDLE_EXCEPTION`. PHP’s source AST is available at `zend_ast_process` before lowering. Compiler constant folding already makes the reverse mapping from opcodes to source ambiguous.
