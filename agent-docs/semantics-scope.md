# Execution semantics scope

## Agreed boundary

- Keep the full [opcode syntax](../spec/00-syntax.watsup). The execution semantics operates on one finalized compilation unit, including its functions, methods, closures and conditional declarations. Both compiler profiles supply inputs.
- Exclude runtime compilation of source and loading additional units, including through an autoloader. A dynamically selected call can still resolve to a body in the unit or a supported builtin. [Zend include and eval](../../php-src/Zend/zend_execute.c#L5354)
- Run one fresh CLI request with fixed initial settings. Supply stdin bytes followed by EOF and collect stdout and stderr separately. The logical filename in the unit is available as data. Filesystem, network, process environment, clock and host randomness are outside scope. Include selected builtins whose behavior can be expressed within the model.
- Exclude host resource limits and allocator measurements. A runner deadline can fail a test run. If either side times out, the comparison has no final PHP outcome from that side.

## Execution policy

- Use the [pinned CLI](fixture-compilation.md) with `-n` for initial PHP settings. Both compiler profiles have effective `error_reporting() == E_ALL`, `display_errors=1` (diagnostics on stdout), `log_errors=0`, `html_errors=0` and `output_buffering=0`. Runtime changes made by a modeled PHP operation apply from that point on.
- File mode passes one script argument. Main's `$argc` starts at `1` and `$argv[0]` contains the path bytes as supplied on the command line. Diagnostics use the filename embedded in the unit. The CLI initializes `$_GET`, `$_POST`, `$_COOKIE` and `$_FILES` as empty arrays. Register lazy globals in the order recorded in the listing. `$_REQUEST` is empty when activated. `$_ENV` imports process-environment entries. `$_SERVER` shares that origin and supplies CLI-specific entries. A local copy can overwrite or delete a key and observe the result independently of the host. Stop when an operation needs unknown host data. [CLI tables](../spec/01-values/09-cli-server.watsup) · [Startup and snapshots](../spec/02-vm/20-globals.watsup) · [Visible order](../tests/project/global_startup_order.phpt)
- Execute literals folded into a unit with their exact bytes, including paths and build strings. Runtime lookup preserves the string type and origin of an installation constant across copies. `PHP_EXTENSION_DIR` and `PEAR_EXTENSION_DIR` come from the same build value. [Zend registrations](../../php-src/main/main_arginfo.h) · [Folded bytes](../tests/project/builtin_installation_literals.php) · [Runtime type and identity](../tests/project/builtin_installation_facts.phpt)
- Define execution on structurally well-formed units. After parsing, `validate_unit` checks every body before execution, including bodies nested inside deferred expressions. It checks literal and frame indices, jump targets, smart-branch pairs, and operand forms for the implemented opcodes. Extend opcode-specific checks as their semantics enter. A typed AST can contain an out-of-range jump, which must be reported before program output. A PHP exception or fatal error during a well-formed execution is a separate outcome. [Structural checks](../src/validate.rs) · [Invalid jump](../tests/project/invalid/missing_target.zop)
- Stop with a plain `UNSUPPORTED` when execution needs an excluded operation, including during binding, implicit calls or shutdown. As milestones progress, this outcome also covers features scheduled for a later milestone. Excluded instructions in an unused function or untaken branch do not trigger it. PHP code cannot catch it. A missing rule for a case declared supported is a spec defect.
- Model runtime warnings and deprecations incrementally with the operations that emit them. Share dispatch of severity, message, PHP filename and PHP line. A matching user handler may handle the diagnostic, return exactly `false` for default processing, or throw. Account for the handler mask, suppression, last-error state and default display as exercised. Compiler diagnostics precede the input unit. [User handler dispatch](../../php-src/Zend/zend.c#L1550) · [Default processing](../../php-src/main/main.c#L1317)

## Choosing what to model

Automatic cycle collection is an approved standing abstraction. Preserve outgoing owners from unreachable cycles until an explicit collection or cleanup removes them. Model last-owner destruction, explicit collection on the actual spec heap and request shutdown under their own rules. Use default Zend for differential testing. Report newly observable effects on explicit collection counts, object destructors, weak references, weak maps or exit status when those features enter. Decide separately whether implementation telemetry in `gc_status()` belongs in scope. [Design decision](../design-docs/automatic-cycle-collection.md)

Pinned Zend defines in-scope behavior. Describe a rule in terms of what a PHP program can observe, including through code that runs later. Abstract a C representation or optimization when replacing it preserves stdout, stderr and exit status for every in-scope continuation. For example, the spec can choose its own representation of ownership. When `unset($x)` releases the last reference to an object, preserve the order of its destructor's output and the following `echo`. [Lifetime and request shutdown, milestone 8](semantics-roadmap.md)

When two rules might differ observably, look for a small program that distinguishes them. A handler can print its arguments, or a `catch` block can inspect a property changed before a throw. For a specialized opcode and an ordinary call, inspect the listings to confirm which path each compiler profile emitted. Preserve each path's observable behavior by default.

- Interpolation ropes store byte fragments by rope and position. Convert each operand at its instruction to preserve warning order, then join the fragments in position order at `ROPE_END`. [String rules](../spec/02-vm/03-strings.watsup) · [Interleaved ropes fixture](../tests/project/rope_indices.zop)
- Integer exponentiation promotes at the first overflowing multiplication. Zend produces adjacent floats for `3 ** 61` and `3.0 ** 61`, so promoting the integer base at the outset would change a strict comparison. [Arithmetic rules](../spec/01-values/03-arithmetic.watsup) · [Power regression](../tests/project/numeric_power_edges.php)
- Array comparison can observe sharing. Zend accepts two occurrences of the same array as equal before comparing its entries, even when an entry is `NAN`. Preserve the array's identity through assignment, element reads and unpacking. [Array comparisons](../spec/01-values/08-array-comparison.watsup) · [Shared and distinct arrays](../tests/project/array_compare_identity.php)
- Switch and match tables store body-local targets in listings. Ordinary array reads of a table can observe the signed opcode-relative byte offsets installed by the native loader. Preserve both views on the pinned build. [Dispatch rules](../spec/02-vm/02-cases.watsup) · [Forward, backward and self targets](../tests/project/array_dispatch_offsets.zop)

Whenever an agent identifies a reason to abstract away an observable Zend behavior, the coordinator reports it to the user as soon as it arises. Subagents pass such findings to the coordinator. Show the pinned and proposed outcomes on a concrete example. Explain the general rule, the evidence that Zend's behavior is incidental, and the cost of matching it. The user decides whether to preserve Zend's behavior or approve the abstraction. Obtain explicit approval before implementing the divergent rule or accepting it in the tests. [Differential suite](differential-testing.md#spec-executable-and-differential-suite)

### Builtins

Share the core operation where Zend's entry points agree. Model argument binding, coercion, diagnostics, and callbacks in their observed order. Keep Zend on the oracle side of the comparison. The evaluator implements supported cases independently and returns `UNSUPPORTED` at the boundary defined above.

- `STRLEN` and an ordinary `strlen()` call both count bytes in a string. In weak typing, passing `null` to either invokes an installed deprecation handler once. If it returns `true`, the length is `0`. If it throws, the exception reaches the caller. [Opcode handler](../../php-src/Zend/zend_vm_def.h#L8895) · [Ordinary builtin](../../php-src/Zend/zend_builtin_functions.c#L376)
- A user-defined `Countable` object's `count()` uses ordinary method execution, including its side effects and exceptions. Some internal classes provide their own counting behavior. [Zend count handler](../../php-src/Zend/zend_vm_def.h#L9619)
